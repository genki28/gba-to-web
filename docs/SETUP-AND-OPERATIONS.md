# セットアップ・実機運用

この文書は、現在の独立Python転送器でGBAのRAMにプログラムを送り、その後Webへ接続するための手順です。2026-11-06時点のローカル実装と既存記録に基づきます。文書作成時にはUSB列挙、実機転送、配線変更、ファームウェア操作を行っていません。

[README](../README.md) / [開発・検証](DEVELOPMENT.md) / [独立転送の調査記録](TRANSFER-RELIABILITY.md)

## 1. 必要なものと対応範囲

- GBA本体と安定した電源。RAM転送時はカートリッジなしの起動ロゴで待機します。
- 既存構成のGBA-PICO-LINK、通信ケーブル、MacにつなぐUSB接続。
- 既存の改変版Celio 2.0.6。上流リリース名 `v1.10.0` と機器が返す `2.0.6` は別の番号です。[上流情報](../gba/vendor/UPSTREAM.md)を参照してください。
- Python 3、USB用仮想環境。Web利用には別リポジトリ `gba-to-web-slide` とPC版Chrome / Edgeが必要です。

以下の `.command` とパス例はmacOS向けです。Windows / Linuxや別アダプターでの実機動作は、このリポジトリの記録からは確認できません。ROMをそのまま使う場合、ARMクロスコンパイラーは不要です。

### 配線について確認できること

接続の構成は「Mac → USB → GBA-PICO-LINK → 既存通信ケーブル → GBA」です。USB機器名は `GBLink USB`、探索するIDはVID `0x2FE3` / PID `0x000A` です。探索対象は1台のみです。

[送信ラッパー](../gba/send.py)は `--cable gba` を固定し、[上流USBコード](../gba/vendor/usb_link.py)ではこの設定が **SDをGP3に割り当てる** モードと定義されています。これはソフトウェア設定の根拠であり、手元の全配線が正しいことを確認するものではありません。

このチェックアウトには、対象個体の全ピン対応・端子方向・電源配線を検証できる回路図や配線写真がありません。SC / SI / SO / GND / 電源などの対応を推測して配線しないでください。端子番号やケーブルの色だけで結線を決めず、[製品の資料](https://booth.pm/ja/items/8533267)と手元の基板仕様、前回確認済みの構成を照合してください。上流コードにある別基板・別ケーブルの説明を、そのまま対象個体へ適用しないでください。

**配線が不明な場合は通電・転送へ進まず確認します。カートリッジの取り外しはGBAの電源OFFで行い、配線を扱う必要がある場合もGBAとUSBの電源を外してから確認してください。BOOTSELやファームウェア書き換えは通常手順ではありません。**

### ファームウェア照会の限界

転送前に `0F 02 00 06` の版応答を要求します。ただし版番号の一致だけでは、必要な改変が入ったファームウェアの内容や配線を証明できません。既知の改変版を使う前提です。異なる版が出ても、ここで更新・再書き込みせず構成を確認してください。

## 2. USB環境の準備（初回のみ）

リポジトリ直下で実行します。すでに `.venv` がある場合は削除・作り直しをせず、先に確認コマンドを試してください。

```sh
cd "$HOME/Desktop/gba-to-web"
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-usb.txt
./Send-ROM.command --check
```

固定依存は `importlib_resources==7.1.0`、`libusb-package==1.0.30.0`、`pyusb==1.3.1` です。インストールはローカル環境とネットワークを使いますが、最後の `--check` はインストール済みメタデータとROMを読むだけです。USBドライバーの初期化・機器列挙・転送は行いません。

ROMだけを確認する場合は次を使います。USBパッケージの有無・版は確認しません。

```sh
python3 -B gba/send.py --check
```

### コマンドの違い

| 操作 | 実際に行うこと |
| --- | --- |
| `./Send-ROM.command --check` | 固定依存パッケージとROMのヘッダー・サイズ・SHA-256を検査。USBなし。 |
| `python3 -B gba/send.py --check` | ROM検査のみ。USBなし。 |
| `python3 -B gba/send.py` | USBを取得し、Cancel → 約1秒排出 → 版照会。ROM本体は送らないが、機器へコマンドを送る。 |
| `./Send-ROM.command` またはダブルクリック | オフライン検査後、USB照会とRAM転送を1回実行。 |

上流 `gba/vendor/mb_multi.py` や `usb_link.py` を通常運用で直接起動しないでください。上流CLIは複数試行や機器再起動など、本プロジェクトのラッパーとは異なる既定動作を持ちます。

## 3. GBAへのRAM転送

### 転送前

1. GBAにすでに `WAITING FOR WEB` が出ているなら、転送を省いて次節へ進みます。
2. 転送が必要なら、GBAの電源OFFでカートリッジを外し、既存配線を確認してから電源を入れ、起動ロゴで待機します。
3. Web側で切断し、他のWebUSBタブ・転送ツールがアダプターを使用していない状態にします。USBを複数プロセスで同時使用しません。
4. `./Send-ROM.command --check` が通ることを確認します。

### 転送実行

```sh
./Send-ROM.command
```

- 試行は1回です。自動再試行・アダプター再起動・ファームウェア書き換えはしません。
- 通常タイミングは3700、初期化待機は70msです。CRCとアドレス計算をraw USB開始前へ移しています。1000ms待機へ変更する過去の案は撤回済みです。
- 転送子プロセスの上限は20分です。約5分という案内は推定で、現行日本語ROMの完走実測ではありません。初期化で失敗すればすぐに止まります。
- 進捗を表示し、`gba/logs/transfer-YYYYMMDD-HHMMSS.txt` に保存します。ファイル名の時刻は実行Macのローカル時刻です。USB事前照会で止まった場合は、新しい転送ログが作られないことがあります。
- 転送に失敗した場合、ラッパーはセッション停止用のCancelを試みます。Cancel失敗が出た場合も、停止できたと決めつけて続けないでください。

### 成功判定を分ける

1. **ROM検査**: ローカルファイルとマニフェストが一致している。
2. **転送完了**: `DONE! CRC 0x....` が出て、プロセスが正常終了した。100%表示だけでは不十分です。
3. **GBA起動**: 実際の画面に `WAITING FOR WEB` が出ている。
4. **Web接続**: Webがv2 heartbeatを受け取り「GBA応答あり」になった。
5. **日本語メモ表示**: 対象メモのIDとCRCが一致した描画ACKをWebが受け取った。

どれか1つの確認で、残りも成功したとは判断しません。過去の試行ではCRCエラー表示後に本人が起動画面を確認しており、画面だけではCRC一致を証明できません。

## 4. 起動済みGBAをWebへ接続

Python転送が終了しUSBを解放した後に、Web側で操作します。Webの詳細は、隣のチェックアウトの `docs/SETUP-AND-OPERATIONS.md` を参照してください。

1. `gba-to-web-slide/Start.command` を起動します。
2. PC版Chrome / Edgeで `http://127.0.0.1:4186/` を開きます。
3. 「GBA接続・メモ」→「起動済みのGBAに接続」を選び、機器選択で「GBLink USB」を選びます。
4. 接続応答、日本語メモの描画完了表示、GBAの実画面を確認します。Web側の接続ではCancel → 排出 → 版照会を経てraw relayを設定します。アダプターの再起動ではありません。
5. A / 右 / Rで次、B / 左 / Lで前へ進むことを確認します。ボタンを押し続ける操作とは分けて、押す・離すを試してください。

Web通信時のタイミング7400は、独立RAM転送時の3700とは別の設定です。エラー対処として一律に同じ値へ変更しないでください。

メモは最大65文字、16pxの13列×5行です。生成済みフォントの対応文字だけを使用し、未対応字や絵文字はWeb側の検査に従って置き換えます。ACKはGBAプログラムが描画を終えたことを示す通信上の確認で、画面の目視確認や認証の代わりではありません。

個人用メモは公開ファイルへ保存しない運用です。ただし選択したGBAには送信され、接続設定の画面には内容が見えるため、画面共有前に設定画面を閉じてください。GBA画面やログを第三者へ共有する場合も内容を確認してください。

### 終了

Web側で切断してからローカルサーバーを終了します。GBAの電源OFFでRAMプログラムは消えるため、次回の起動には再転送が必要です。終了や再接続のためにBOOTSEL・ファームウェア変更を行う必要はありません。

## 5. 困ったとき

| 症状 | まず確認すること |
| --- | --- |
| `.venv/bin/python` がない / パッケージの版違い | 初回セットアップを確認し、固定版を仮想環境へ入れる。ROMだけの検査と依存検査を区別する。 |
| ヘッダー・サイズ・SHA-256不一致 | 転送しない。ROMと `rom-manifest.js` の組を確認し、開発手順で生成物を整合させる。ハッシュ検査を無効にしない。 |
| `Expected one GBLink, found 0` / 複数台 | 対象アダプターが1台か、MacへのUSB接続と既存構成を確認する。機器IDだけで正しいファームウェアと断定しない。 |
| USB使用中 / claim失敗 / 版応答なし | WebUSB接続や他ツールを終了したか確認する。版照会にもUSB書き込みがあるため、調査目的で繰り返し起動しない。抜き差し等が必要なら、処理停止とGBAの状態を確認して本人が判断する。 |
| ヘッダーや `lunghezza:0000` で停止 | 本体転送前の失敗。過去にも記録あり。新しいログの末尾と `[usb-diagnostic]`、GBA表示を保存し、待機値・配線・ファームウェアを推測で変更しない。 |
| データ途中 / 3秒無応答で停止 | 停止位置、`last_error`、受信回数、両受信スレッドの状態を確認する。USB・アダプター・GBAのどこが原因かはログだけでは確定できない。 |
| 100%の後にCRC不一致 | 完了扱いにしない。GBA表示とCRCのログを別々に記録し、自動再転送しない。 |
| 接続したのに「GBA応答あり」にならない | 起動画面・Python転送終了・対応ROMを確認する。旧heartbeat `D301` はv2と非互換。メモACK不成立と接続不成立を区別する。 |
| メモが反映されない / ボタンが効かない | 対応文字・65文字以内・メモID/CRCのACK・現在のWeb接続を確認し、画面と操作結果を記録する。実機の総合動作は未検証。 |

再実行を重ねず、発生時刻、実行コマンド、GBA画面、最後のエラー、該当ログを残してください。診断の詳細は[独立転送の調査記録](TRANSFER-RELIABILITY.md)にあります。診断v2は直近32パケット・32書込・64プロトコル応答の観測情報を上限付きで保持します。ホスト時刻の記録であり、物理ケーブル上のタイミング測定ではありません。

## 6. 残っている確認

- 最新診断追加後の独立転送の完走、CRC一致、継続した実機動作。
- 現行ROMとWebによる接続、日本語表示、描画ACK、A/B/方向/L/R操作の一連の確認。
- 対象個体の全ピン配線と他OS・別ハードウェアでの動作。

ホスト上のテストや版照会成功だけでは、これらは検証できません。[実機テストの時系列記録](HARDWARE-RUN-2026-11-05.md)を引き継ぎ、次回の観測を分けて記録してください。
